

## Веб-логи (только для отладки)

Компонент `components/web_log` включается через `idf.py menuconfig` →
`Robot web logging` → `Enable Wi-Fi WebSocket log viewer`.
По умолчанию он выключен: исходник сервера и HTML не включаются в сборку,
вызов запуска исключён через `CONFIG_ROBOT_WEB_LOG`.

При включении робот создаёт точку доступа `Robot-Debug-forward` или `Robot-Debug-goalkeeper`, пароль `robotdebug`
(оба параметра меняются в menuconfig). Подключитесь к ней и откройте
http://192.168.4.1. Интернет и внешние библиотеки странице не нужны.
Страница получает `ESP_LOG*` через WebSocket, поддерживает фильтр, паузу,
очистку и скачивание показанного журнала. Пауза останавливает отображение,
приём продолжается. В браузере хранятся последние 2000 строк.

На ESP32 хранятся 64 фрагмента по 255 байт, длинные записи обрезаются.
При переполнении старые фрагменты вытесняются с уведомлением о потерях.
Отправка выполняется примерно каждые 100 мс задачей HTTP на ядре 0,
приоритет 1. Медленные клиенты отключаются при ошибке отправки.
UART сохраняется; его существующие задержки этот модуль не устраняет.
Журнал только оперативный: записи до запуска модуля, сбросы и panic не
сохраняются. Без подключённого браузера журнал также выгружается и очищается.

**Вратарь (robot_type=1):** при активной сборке веб-логов датчик линии
полностью отключён (без инициализации GPIO/ADC2 и чтения). API угла
возвращает 360°, направление — (0, 0); калибровка ничего не меняет.
В info_menu показано `WIFI mod` (латиница для шрифта OLED).
При выключенных веб-логах датчик работает штатно. Ошибка запуска сервера
не включает датчик обратно в этой отладочной сборке.

Для раздельных конфигураций отладки и матча используйте отдельные файлы
sdkconfig и каталоги сборки (запускайте из корня проекта):

```sh
idf.py -B build-web-debug -D SDKCONFIG=sdkconfig.web-debug-local -D 'SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.web-debug' build
idf.py -B build-match -D SDKCONFIG=sdkconfig.match-local -D 'SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.match' build
```

Для матча прошивайте именно `build-match`. Файлы `*-local` должны быть новыми
при первом запуске: defaults не перезаписывают уже сохранённый sdkconfig.
Перед использованием на движущемся роботе проверьте задержки управляющего
цикла под нагрузкой и при потере связи.

### Быстрый выключатель без изменения sdkconfig

В отладочной конфигурации один раз включите `CONFIG_ROBOT_WEB_LOG`.
Дальше меняйте `ROBOT_WEB_LOG_ENABLED` в
`components/web_log/include/web_log_config.h`: `0` — выключен, `1` — включён.
Обычный `idf.py build` пересоберёт зависимые исходники и перелинкует прошивку,
не меняя конфигурацию ESP-IDF. После изменения нужно прошить робота.
При `0` код реализации и вызов запуска исключаются препроцессором:
модуль не запускает Wi-Fi, задачи и перехват логов. Поддержка WebSocket в
ESP-IDF остаётся собранной. Для полной конфигурации матча по-прежнему
используйте `sdkconfig.match`, который исключает также исходник и HTML.

К базовому SSID автоматически добавляется `-forward` или `-goalkeeper`.
Если имя превышает 32 байта, сокращается базовая часть, суффикс сохраняется.
