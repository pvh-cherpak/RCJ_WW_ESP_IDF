

## Веб-логи (только для отладки)

Компонент `components/web_log` включается через `idf.py menuconfig` →
`Robot web logging` → `Enable Wi-Fi WebSocket log viewer`.
По умолчанию он выключен: исходник сервера и HTML не включаются в сборку,
вызов запуска исключён через `CONFIG_ROBOT_WEB_LOG`.

При включении робот создаёт точку доступа `Robot-Debug`, пароль `robotdebug`
(оба параметра меняются в menuconfig). Подключитесь к ней и откройте
http://192.168.4.1. Интернет и внешние библиотеки странице не нужны.
Страница получает `ESP_LOG*` через WebSocket, поддерживает фильтр, паузу,
очистку и скачивание показанного журнала. Пауза останавливает отображение,
приём продолжается. В браузере хранятся последние 2000 строк.

На ESP32 хранятся 64 фрагмента по 255 байт, длинные записи обрезаются.
При переполнении старые фрагменты вытесняются с уведомлением о потерях.
Отправка выполняется примерно каждые 100 мс задачей HTTP на ядре 0,
приоритет 1. Медленные клиенты отключаются при ошибке отправки.
UART сохраняется; его существующие задержки этот модуль не устраняет.
Журнал только оперативный: записи до запуска модуля, сбросы и panic не
сохраняются. Без подключённого браузера журнал также выгружается и очищается.

**Вратарь (robot_type=1) не запускает модуль:** его датчик линии использует
ADC2, конфликтующий с Wi-Fi. До переноса на ADC1 или внешний АЦП отлаживать
его этим способом нельзя. Ошибка запуска веб-логов не останавливает робота.

Для раздельных конфигураций отладки и матча используйте отдельные файлы
sdkconfig и каталоги сборки (запускайте из корня проекта):

```sh
idf.py -B build-web-debug -D SDKCONFIG=sdkconfig.web-debug-local -D 'SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.web-debug' build
idf.py -B build-match -D SDKCONFIG=sdkconfig.match-local -D 'SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.match' build
```

Для матча прошивайте именно `build-match`. Файлы `*-local` должны быть новыми
при первом запуске: defaults не перезаписывают уже сохранённый sdkconfig.
Перед использованием на движущемся роботе проверьте задержки управляющего
цикла под нагрузкой и при потере связи.

### Быстрый выключатель без изменения sdkconfig

В отладочной конфигурации один раз включите `CONFIG_ROBOT_WEB_LOG`.
Дальше меняйте `ROBOT_WEB_LOG_ENABLED` в
`components/web_log/include/web_log_config.h`: `0` — выключен, `1` — включён.
Обычный `idf.py build` пересоберёт зависимые исходники и перелинкует прошивку,
не меняя конфигурацию ESP-IDF. После изменения нужно прошить робота.
При `0` код реализации и вызов запуска исключаются препроцессором:
модуль не запускает Wi-Fi, задачи и перехват логов. Поддержка WebSocket в
ESP-IDF остаётся собранной. Для полной конфигурации матча по-прежнему
используйте `sdkconfig.match`, который исключает также исходник и HTML.

## Настольный симулятор RoboCupJunior Soccer

Сборка симулятора запускается отдельно от ESP-IDF. Для окна нужен raylib 5.5.
CMake использует установленный пакет или загружает исходники raylib при первой
конфигурации. Для сборки raylib под Linux нужны зависимости оконной системы.
Для готового пакета укажите `-DRCJ_RAYLIB_ROOT=/путь/к/пакету`.
Для шрифта Comic Sans MS положите оригинальный файл `comic.ttf` рядом
с исполняемым файлом `rcj-sim`, например в `build-sim/`.

```bash
cmake -S sim -B build-sim
cmake --build build-sim
./build-sim/rcj-sim --profile sim/field.conf --sensors sim/sensors.conf
./build-sim/rcj-sim --scenario sim/match.conf --output match.rcj
```

По умолчанию на поле один вратарь. `--robots 2` добавляет нападающего,
`--robots 4` включает игру 2×2. В `sim/match.conf` можно менять команды, роли и
начальные позиции. Размеры поля и параметры роботов находятся в
`sim/field.conf`. Размеры по умолчанию предназначены для обкатки. Для своего
турнира подставьте размеры фактической площадки.

В `sim/field.conf` также задаются коэффициенты только для симулятора.
`maxSpeed`, `acceleration` и `turnRate` определяют отклик на команды привода.
`ballDrag`, `spinDrag`, `floorGrip`, `wallBounce` и `bodyBounce` задают физику мяча.
`cameraUnitsPerMeter` и `locatorFalloff` калибруют средние показания датчиков,
а `sim/sensors.conf` задаёт их шум, частоту и задержки. Коэффициенты
`keeper*`, `forward*` и `clearRound` можно менять для стратегии в симуляторе.
Передайте профиль через `--profile` и перезапустите окно после правки файла.

Чтобы добавить коэффициент стратегии, внесите его имя, значение по умолчанию
и диапазон одной строкой в `main/soccer_coefficients.def`. В контроллере
используйте поле `gains.<имя>`. После пересборки это же имя можно указать
в профиле. Команда `./build-sim/rcj-sim --strategy-keys` выводит имена
и значения по умолчанию в формате профиля. Для изменения значения уже
зарегистрированного коэффициента достаточно отредактировать профиль
и перезапустить симулятор.

Для отдельного набора значений при сборке скопируйте `main/soccer_coefficients.def`
и передайте абсолютный путь к своей копии. Оставьте в ней поля, которые
использует код стратегии.

```bash
cp main/soccer_coefficients.def simulator_coefficients.def
cmake -S sim -B build-sim -DRCJ_SIM_COEFFICIENTS_FILE="$PWD/simulator_coefficients.def"
cmake --build build-sim
./build-sim/rcj-sim --strategy-keys
```

Значения из выбранного файла используются при запуске по умолчанию.
Строки из переданного `--profile` имеют приоритет. Чтобы применить
новые значения из сборки с сохранённой геометрией поля, уберите
соответствующие строки коэффициентов из копии `sim/field.conf`.

- Левая кнопка мыши тянет мяч или робота через физику. На паузе она ставит
  объект в свободную точку и сбрасывает его скорость.
- Space ставит игру на паузу. N выполняет один цикл управления. Tab меняет
  наблюдаемого робота. R возвращает начальную расстановку.
- C и L переключают шум камеры и локатора. Ползунки справа меняют шум,
  FPS камеры и время считывания. Белый луч показывает команду движения,
  оранжевые лучи показывают реальный и измеренный азимут мяча, цветные лучи
  показывают наблюдения ворот.
- F5 сохраняет последние 30 секунд в `soccer.rcj` или в файл из `--output`.

`cameraFps` задаёт частоту кадров отдельно от `cameraReadMs`. Для локатора
время считывания задаётся через `locatorReadMs`. Пока чтение идёт, контроллер
использует последнее доступное измерение. Физика обновляется каждые 5 мс,
контроллер читает датчики каждые 10 мс. Переключатели шума оставляют тайминги
датчиков активными. Профиль содержит приблизительные значения для дальности
камеры и силы локатора. Их следует сравнить с логами реального робота.

```bash
./build-sim/rcj-sim --replay soccer.rcj
./build-sim/rcj-sim --replay soccer.rcj --compare
cmake -S sim -B build-sim-headless -DRCJ_SIM_GUI=OFF
cmake --build build-sim-headless
ctest --test-dir build-sim-headless --output-on-failure
./build-sim-headless/rcj-sim --replay soccer.rcj --headless
```

Повтор рассчитан на локальные записи той же сборки. `--compare` заново
инициализирует контроллеры в сохранённой расстановке. Контроллеры вратаря и нападающего используют общий с прошивкой код.
Блокирующие манёвры нападающего переведены в последовательность шагов по
10 мс. Механика и показания датчиков аппроксимированы. Касания внешней стены и заходы в штрафную видны в журнале.
